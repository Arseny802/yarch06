# Планирование: анализ, идентификация проблем и поиск решений
## 1. Анализ схемы и описание системы

Система ювелирного магазина «Александрит» состоит из нескольких компонентов:

* онлайн-магазин (Vue, Java Spring Boot);
* CRM (Vue, Java Spring Boot);
* MES (React, C#);
* хранилище 3D-файлов;
* очереди сообщений (RabbitMQ);
* базы данных (PostgreSQL).

Система позволяет клиентам загружать 3D-модели ювелирных изделий или создавать их с помощью конструктора, а также оформлять заказы. Продавцы работают с CRM, операторы — с MES. API позволяет внешним пользователям отправлять запросы и получать данные.


## 2. Выявленные проблемные места:

* Задержки в обработке заказов. Клиенты жалуются на длительные сроки выполнения заказов. Несмотря на то что производственные мощности позволяют справиться с нагрузкой, заказы обрабатываются медленно.
* Проблемы с производительностью MES. Операторы сообщают о длительном времени загрузки первой страницы MES, где отображается список заказов. Фильтры и пагинация не решили проблему.
* Увеличение нагрузки на систему. С ростом числа заказов и добавлением новых клиентов через API система испытывает дополнительную нагрузку.
* Задержки релизов из-за багов. QA-инженер обнаруживает баги уровня high или highest, что приводит к задержкам в деплое на продакшн.
* Длительное время расчёта стоимости заказа в MES. Для сложных и детализированных моделей время обработки может достигать 30 минут.


## 3. Инициативы для устранения проблем:

* Оптимизация производительности MES:
* * провести аудит кода и базы данных MES, выявить узкие места;
* * рассмотреть возможность масштабирования MES (например, добавить дополнительные инстансы);
* * оптимизировать алгоритмы обработки данных, особенно для отображения списка заказов;
* * улучшить кэширование данных, чтобы снизить нагрузку на базу данных.

* Улучшение процессов обработки заказов:
* * проанализировать поток заказов и выявить «бутылочные горлышки»;
* * оптимизировать взаимодействие между CRM и MES через RabbitMQ;
* * внедрить дополнительные механизмы мониторинга и оповещения о задержках в обработке заказов.

* Масштабирование инфраструктуры:
* * увеличить ресурсы (CPU, память, дисковое пространство) для ключевых компонентов системы (онлайн-магазин, CRM, MES);
* * рассмотреть возможность горизонтального масштабирования (добавление дополнительных инстансов) для компонентов, испытывающих высокую нагрузку.

* Улучшение процесса тестирования и развёртывания:
* * автоматизировать тестирование наиболее критичных сценариев, чтобы сократить время обнаружения багов;
* * внедрить более строгие критерии для классификации багов, чтобы избежать необоснованных задержек в релизах;
* * рассмотреть возможность сокращения времени цикла разработки и тестирования.

* Оптимизация расчёта стоимости заказа:
* * исследовать возможность параллельной обработки расчётов для нескольких заказов;
* * использовать более мощные вычислительные ресурсы для расчётов стоимости;
* * разработать алгоритмы, позволяющие ускорить обработку сложных 3D-моделей.


## 4. Приоритет инициатив:

1. Оптимизация производительности MES. Это критически важно, так как проблемы с MES напрямую влияют на работу операторов и, следовательно, на сроки выполнения заказов.
2. Улучшение процессов обработки заказов. Оптимизация потока заказов поможет сократить сроки их выполнения и улучшить удовлетворённость клиентов.
3. Масштабирование инфраструктуры. Увеличение ресурсов и горизонтальное масштабирование позволят системе справляться с растущей нагрузкой.


## 5. Целевая архитектура через полгода:

* MES с улучшенной производительностью, способное быстро обрабатывать запросы операторов.
* Оптимизированный поток заказов, обеспечивающий их быструю обработку и отправку клиентам.
* Масштабируемая инфраструктура, способная справляться с увеличением числа заказов без потери производительности.
* Автоматизированные процессы тестирования, сокращающие время выявления и исправления багов.
* Ускоренный расчёт стоимости заказа, даже для сложных 3D-моделей.


## 6. Три приоритетных пункта для выполнения в ближайшие полгода:

1. Оптимизация MES. Без решения этой проблемы операторы продолжат сталкиваться с задержками, что скажется на сроках выполнения заказов.
2. Анализ и оптимизация потока заказов. Это позволит сократить время обработки заказов и улучшить взаимодействие между CRM и MES.
3. Масштабирование инфраструктуры. Рост нагрузки требует увеличения ресурсов системы, чтобы обеспечить её стабильную работу.
